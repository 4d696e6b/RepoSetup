# RepoSetup 0.3.0 intended-stack doctor

Run `reposetup doctor --config reposetup.json` from the project directory to compare a schemaVersion 1 config with local evidence. If `project.path` is present and is not `.`, it names a child project relative to the current directory; symlinked paths and paths that do not identify that project's root are refused. `doctor` without `--config` retains discovery-only behavior. These checks are read-only: they may query tool versions but never install packages or change project files. The separate `--fix` workflow below can create allowlisted files after review.

The config is parsed and resolved against the built-in registry before local checks. The intended mode checks runtime, package-manager and framework evidence; the requested TypeScript option; every explicitly selected integration's registry verification; direct dependency declarations from the selected registry recipes; and generic prerequisite, lockfile and environment guidance. It runs expected integration verification even if normal detection no longer finds the integration. Missing direct declarations use `INTENDED_DEPENDENCY_MISSING`; failed intended integration verification uses `INTENDED_VERIFICATION_FAILED`; runtime, manager, framework and TypeScript evidence conflicts use `INTENDED_CONTEXT_MISMATCH`. Malformed configs retain `CONFIG_INVALID` and other existing input errors.

Dependency declarations and discovered files are evidence, not proof that a package is installed or an app runs. A declared version or range that differs from a recipe pin is informational because this check does not establish compatibility; the observed declaration is not echoed. An explicit runtime version difference is also informational unless an existing prerequisite check establishes a failure. Extra detected integrations are informational and never proposed for deletion. Registry verification handles alternative supported config files, such as Prettier's recognized locations. The checker does not infer arbitrary missing files from generator output or read `.env` values.

`--json` preserves the version 1 doctor envelope (`kind: "doctor"`, `result`, `failed`). In intended mode, `result.mode` is `"intended"`; checks may add `level: "info"`, `confidence`, and structured `evidence`. Input errors retain the version 1 error envelope. Text output labels the intended mode, shows informational differences, and includes evidence with `--verbose`.

## Narrow repair workflow

`reposetup doctor --config reposetup.json --fix --dry-run` shows a structural file preview without writing. `--fix` without `--dry-run` shows the preview and asks for confirmation; `--yes` confirms in a noninteractive terminal. `--fix` requires an intended config, and `--dry-run` and `--yes` require `--fix`. A dry-run exits with the current doctor's failure code if findings remain. Text output shows manual guidance; JSON retains the version 1 doctor envelope and adds a `repair` object with counts, guidance, dry-run state, and a content-free preview. Before JSON execution, the preview is written as a separate `doctor-repair-preview` object to stderr; the final doctor report is written to stdout.

Only missing `.prettierrc` for a qualified React/Vite or Express recipe and missing `.env.example` for a matching Prisma SQLite/PostgreSQL or FastAPI/Pydantic Settings recipe are eligible. The Prettier verifier recognizes supported alternative config locations. Repair requires matching registry recipe pins, compatible context, no other failing health checks, and, for environment examples, an exact match to the registry's generated source template. Placeholder keys and values come only from registry operations; RepoSetup never reads `.env` contents. Existing files, including a user-edited `.env.example`, are never edited or overwritten.

Confirmation rechecks the file preview, config, health findings, and recipe eligibility. The normal executor creates files exclusively, then doctor reruns and reports any remaining findings. Repeating a successful repair is a no-op. Missing dependencies, changed recipe versions, conflicting source files, unqualified recipes and other unsupported findings receive manual guidance; doctor does not reinstall dependencies, regenerate locks, restore source, or install system software.
